# 指环指挥 · 关卡

浏览器里的关卡。音乐按固定速度走，人跟着打。音符的来法照 Maestro：从远处朝你飞来，落在判定圈上的那一刻出手。界面是深色、冷色霓虹的 Cytus II 风格。

## 打开

```bash
npm install
npm run dev
```

浏览器打开终端里的本地地址。第一次点击关卡时才会出声。

## 怎么玩

先听一小节倒数（每拍一声滴答），然后跟着音符打。右侧判定圈是右手：带箭头的圆形音符飞向判定圈，通常边飞边朝它要你挥的方向移动；为避免遮挡，向下的音符从右下方斜向判定圈飞来，仍要按箭头向下挥。上下是屏幕上的上下，不是前后。左侧判定圈是左手：六边形音符标示小提琴 / 长笛的进入，或以渐强、渐弱的力度记号和上下箭头提示动作。音符落到圈上时按下对应方向。右手用方向键，或在画面右半边滑动（滑出一小段就算，不用等松手）。左手点小提琴、长笛，他们才进来。E 是渐强，D 是渐弱，也可以在左半边上下滑。

每个左手记号都和一次右手击拍落在同一拍上，因此两只手总是同时出手，不必分别数两套节奏。

关卡中判定圈位于双手前方、离玩家更远的画面层；挥动时手会暂时移动并回位。右手挥动在 3D 画面里始终是上、下、左、右平移，不会前后移动。左手抬掌和压掌带动前臂缓慢地沿屏幕上下移动并回位，手腕保持平稳；向前一指则伸向乐团。这些是手势动画，并非真实手部位置追踪；动画速度不改变判定时间或戒指识别要求。

- Perfect：离这一拍 120 毫秒以内
- Good：250 毫秒以内
- Miss：更远，或这一拍没有打

每个音符命中时会显示「偏早 / 偏晚」。结束页统计偏早、偏晚的次数和平均偏差，并在设置里给出建议的「判定延迟」。

首页在原来的三首练习之后，还有四首按真实声部编的曲子：卡农、欢乐颂、蓝色多瑙河、小夜曲。小提琴、长笛、圆号、大提琴、钢琴从左到右坐开。一段曲子里哪只手打拍、什么时候放手、什么时候双手重音，跟着音乐走，不要求每一拍都用右手。指、圈选和渐强渐弱直接亮在对应的声部上，渐强在整段时间里抬手都算。乐手只在自己的声部出音符时才动，动作长短和大小跟那个音符一致。

判定比音游宽：Perfect 150 毫秒，Good 400 毫秒。方向错了但时间对，算 Good。方向认不出时，只按时间算。

关卡有三首，节拍声（鼓点）每拍都响，音符就落在鼓点和钢琴和弦上：

| 关卡 | 拍号 / 速度 | 内容 |
| --- | --- | --- |
| 第一乐章 · 晨光 | 4/4，80 BPM | 8 小节。第 3 小节起点小提琴，第 5 小节起点长笛，第 6 小节渐强，第 7 小节渐弱 |
| 第二乐章 · 圆舞 | 3/4，92 BPM | 8 小节。圆舞曲节奏，同样点名两个声部，一次渐强、一次渐弱 |
| 第三乐章 · 凯旋 | 4/4，108 BPM | 12 小节。进行曲；第 7、8 小节只打 1、3、4 拍；两次渐强、两次渐弱 |

关卡数据在 [src/chart.js](src/chart.js)（谱面和音乐都由它生成，见 [src/score.js](src/score.js)）。

## 自由指挥 · 萨蒂

舞台上有小提琴、长笛、圆号、大提琴和钢琴。挥第一拍或按 F 起奏。点选、按 1–5 或用鼠标画圈选中乐手，再用 F 或左手戒指前指，让选中的声部在下一拍加入。G 或握拳停下选中的声部。未选中乐手时，G 或握拳在小节末收束全团。

S 让选中的一位乐手在下一个两小节边界接过主旋律，其他声部继续伴奏并让出音量。再按 S 可以恢复合奏。用 E/D 或抬掌/压掌调节选中声部的力度，未选乐手时调节全体。所有声部按挥拍共用同一条可变速时间轴。

乐谱源于 Erik Satie 的《第一号吉诺佩第》，采用 Paul De Bra 基于 Claude Debussy 配器制作的[合奏编配](https://www.de-bra.nl/arrangements.html#gymnopedie-1)，按 [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/) 授权。游戏取五条有音高的声部，改用游戏内管弦乐器音色，省略吊镲。用 `python3 tools/gymnopedie-to-score.py` 可从随附 MuseScore 源文件生成游戏数据。

## 设置

页面右上角「设置」里可以手动调「判定延迟」（−400 到 +400 ms，保存在浏览器里）。总是偏晚就调大，总是偏早就调小。它只改判定时间，不改画面。游戏已经自动扣除了音频调度提前量和设备输出延迟。

指环面板和设置面板点击面板以外的地方会自动收起，开始关卡时也会收起，不会遮挡舞台。

## 这一版没有

戒指不能判断圈选范围或指向目标。古典关卡中的画圈使用鼠标或触控。

## 用两枚戒指玩节奏关卡

每枚戒指一只手，手势都在浏览器里实时识别（[src/ring/detectors.js](src/ring/detectors.js)）：

| 手势 | 戒指 | 作用 |
| --- | --- | --- |
| 打拍 | 右手 | 检测角速度峰，并在重力坐标里判断上、下、左、右（默认免校准）；同时判方向和时间 |
| 点名（向前一指） | 左手 | 线加速度冲击；关卡中回应当前待进入的声部，自由模式中让选中声部起奏 |
| 抬掌 / 压掌 | 左手 | 去重力后的竖直速度，取起手 0.45 秒内最强的一笔方向；自由模式中调整选中声部或全体力度 |
| 画圈 | 左手 | 戒指检测完整一圈。古典曲目中选择谱面指定的声部，自由指挥中选择当前对准的声部 |
| 握拳 | 任一只手 | 自由指挥中收束乐团或选中的声部，古典曲目中回应曲末的收束提示 |

键盘、鼠标只在对应那只手**没有在线戒指**时才生效：右手戒指在线时，方向键和右半屏滑动被忽略；左手戒指在线时，点乐手、E/D 和左半屏滑动被忽略。只戴一枚时，另一只手仍可用键鼠。

### 启动

1. 按 Ringo 实验室的说明启动 `ring-studio`，连接两枚戒指（本机 TCP `127.0.0.1:17888`，只发 IMU）。
2. 终端 A：`npm run ring` — 把 TCP 转成浏览器能用的 WebSocket（`ws://127.0.0.1:8787`，只接受本机页面）。
3. 终端 B：`npm run dev`，打开页面。右上角「指环」按钮显示连接状态。
4. 点开「指环」面板：只有已连接且在发数据的戒指才会显示并分配左右手（Ring Studio 记录过的离线戒指会被忽略）。两枚都在线时按地址排序，较小的当右手；分反了点「交换左右」，选择会记在浏览器里。
5. **不需要校准，直接开始。** 默认使用「免校准（重力坐标）」：方向由重力方向推算——左右看旋转绕竖直轴的分量，上下看手被驱动时沿重力的加速度。这两者对每个人都一样，戒指在手指上怎么转、换谁戴都不影响，所以没有要采集的动作，两只手都不用。在 164 段带标注的录制上（三位佩戴者）识别 162 段；丢帧 10%、20% 时仍为 99%，30% 时 98%。

   需要注意的是：这 164 段都是同一个方向反复挥动的录制，而关卡要求四个方向轮换，每一拍的形状又取决于上一拍手停在哪里。免校准模式在真实关卡里还没有被测量过，手势记录里的 `transitions` 就是为看这件事准备的。

   若识别不准，「指环」面板里可切回「校准模板（备用方式）」——**以下是备用方式的校准步骤**：左右手校准互不依赖，可以先校准任意一只。左右手校准互不依赖，可以先校准任意一只。确认对应戒指在线后，右手点「开始连续校准」，先短暂停稳以估计右手陀螺仪静止偏置，随后按提示依次向下、左、右、上各挥动 3 次；左手点「开始左手校准」，按提示上抬、下压手掌各 3 次。左手只需校准上下动作，不需要右手先完成。右手每次看到「现在向……挥动」后，按游戏中的方式挥动并迅速回位；回位后短暂停稳，等待下一次提示，无需逐次点击。右手连续校准可随时停止并继续已采集的进度；若数据不足会重试当前动作，超时停止后可再次点击继续，每次动作有 15 秒采集时间。若某个方向有问题，打开「补录某个方向」，选择方向后按照提示连续采集 3 次；该方向原样本会被清除，其他方向保留。左手校准可随时停止，重新开始会清除本次样本。对应戒指在线时，开始关卡前需完成该手校准。校准和静止偏置只保存在当前页面；刷新、切换对应手的戒指或断连后要重新校准，改变佩戴位置或姿势后也建议重新校准。
6. **（可选）开启摄像头。** 首页会询问一次，也可以随时在「指环」面板里开关。摄像头原本是为了补上校准模板方式的一个盲点：在戒指自己的坐标里，下挥和上挥的回程相差约 166 度，几乎是同一个旋转，没有任何阈值能把两者分开。**默认的免校准方式没有这个盲点**——重力本身就是绝对的竖直参考——所以在免校准模式下摄像头只在戒指拒判时补一个方向，不会否决戒指已经给出的判断（戒指在标注录制上为 99%，摄像头在已记录的对局中约为 53%）。切回校准模板方式时，摄像头仍按原来的规则参与上下判定。不开摄像头完全不影响游玩。
   开启后请对照预览里的虚线框摆好双手，并**试着完整地挥一次下拍**：如果手挥到框外，把屏幕往后仰一点——笔记本摄像头常常看不到完整的下挥，而那正是摄像头要解决的方向。右上角的「摄像头」按钮显示当前状态；手不在画面内时它会变黄，此时判定自动退回只用戒指，不会打断游戏。
   模型和推理都在本机运行，画面不会离开这台电脑，也不需要联网。
7. 选关并跟随箭头挥动。面板「最近手势」显示左右手识别结果；若右手显示「方向不确定」，该动作不会被当成正确拍点，并会显示可能原因。拍子方向错误记 Miss。面板里的「平均偏差」只统计本次关卡中方向正确且落在判分窗口内的右手击拍；正数表示拍子偏晚，可点「采用」调整补偿（也可以用 −/+ 手动调，每次 10 ms，或点「归零」重置）。这是已识别样本的偏差，不代表漏判、误判动作的整体延迟。

### 录制动作与整局游戏

启动 Ring Studio、`npm run ring` 和 `npm run dev` 后，从同一个本机地址打开 `/tools/gesture-capture.html`。在采集页选双戒指或单手录制，再按设备地址指定左右手。每组动作结束后会自动保存并选择下一组。

用「打开游戏并录制」在采集页内选关，游戏会保存整局 IMU 和判定记录。文件默认写到项目目录旁的 `output/ringsymphony-captures`，动作组在 `groups`，整局在 `games`。

在《卡农》第 9 小节或《小夜曲》第 13 小节，等「准备」消失，用左手在身前画一整圈。握拳在曲末「收束」提示出现时完成。自由指挥里可用鼠标对准声部，或通过摄像头指向声部，再用左手画圈选中。

### 摄像头如何参与判定

- **时间永远由戒指决定。** 戒指 200 Hz，摄像头约 30 fps 且有 50–100 ms 管线延迟，所以摄像头不进入计时路径；画面里的手在戒指事件到达时立刻响应，不等任何一帧。
- **上下由摄像头说了算**（在它有把握时）。左右仍以戒指为准：左右相差约 95 度、回程走的弧线也不同，戒指在这个轴上并不瞎，没有必要让摄像头去改它。
- **戒指认不出方向时，摄像头补上**，左右上下都算。这类情况原本只会显示「方向不确定」且不得分，所以补上只会把零分变成有分。
- **有把握**的定义是：这只手在判定窗口里一直被跟到、没有贴着画面边缘、位移超过噪声门限。任何一条不满足就退回只用戒指——没有摄像头、权限被拒、跟丢、光线不足、帧率骤降，走的都是同一条路径。
- 摄像头的窗口取击拍**之前**的 300 ms。回程发生在击拍之后，因此永远不会被看到——这正是戒指单独解决不了、而两个传感器合起来就自然解决的问题。

「指环」面板里可以导出两者判断不一致的记录（JSON），用于以后标注和改进；记录保存在本机浏览器里，刷新和重开都在，可随时清除。

面板分别显示左右手最近 2 秒的手势和递增编号，可用来区分新误触发与之前的结果。「峰后」是设备时间里动作峰值到检测器发出结果的间隔，不包含蓝牙传输、桥接或画面刷新，不能作为端到端延迟。右手要等角速度峰值出现并回落才报告击拍；左手抬/压掌需要观察 450 ms 的动作窗口。延迟补偿只调整判分时间，不会让画面提前响应。

挥拍起势后，双手都可以在方向连续几帧保持一致、并与当前拍点方向吻合时预先播放小幅动作。免校准模式还会检查数据流是否连续。正式拍点和得分仍在挥拍确认后更新。戒指面板显示最近动作的起势到峰值、峰值到确认和预览提前量，便于检查设备和识别延迟。

采集页位于 `/tools/gesture-capture.html`。选择录制范围并指定戒指，填写佩戴者 ID，放下戒指静置至少 3 秒，等近 5 秒的采样检查变绿后开始。采样率低于 150 Hz 或帧间隔超过 50 ms 的录制需要主动勾选并确认强制录制。节拍器支持 80、100 和 120 BPM，记录目标拍点、方向和实际显示时间。结束后会显示每只戒指的帧率、最大间隔、丢包和断流。建议重录的文件会保存，但不计入本组完成进度。

`python tools/train-causal-model.py recordings --out <本地文件>` 可训练线性分类器，并按佩戴者或录制组交叉验证。可在目录参数中加入采集页的本地保存目录。验证合格的权重可放在 `public/causal-model.json`。默认使用规则识别。节拍器记录的是目标拍点，实际出手峰值仍需结合 IMU 和其他标注核对。

面板的右手候选统计按页面累计，可手动清零。它区分方向已识别、数据不足或断帧、信号弱、与校准差异大、方向相近、未校准和回程抑制；与校准差异大还区分方向窗口中是否有超过 30 ms 的间隔。统计只包括检测到的击拍候选，不包含未触发检测器的动作，也不代表游戏判分正确。数据不足不一定由断帧引起；无明显间断也不能证明没有缺帧。

### 没有戒指时检查链路

回放工具把 [recordings/](recordings) 中已有的 IMU 数据循环发送，模拟两枚戒指；它不是录像，也不会录制新动作。默认右手播放「四拍/yyh」，左手播放「上升/lry」。

在项目目录中打开三个终端，分别运行：

```bash
npm run replay
npm run ring
npm run dev
```

如果网页或桥接已经启动，无需重复启动。打开开发服务器输出的网页地址，在「指环」面板查看模拟设备和最近手势；不要使用指向其他 WebSocket 地址的 `ring` 参数。结束时分别在运行中的终端按 Ctrl+C。

模拟器和真实 Ring Studio 默认都使用 TCP 端口 17888，不能同时占用该端口。回放只用于检查数据链路和识别，不与关卡节奏同步；固定录制也不能按校准提示改变动作，因此不能替代真实戒指完成校准和游玩。

### 校验识别

`npm run eval` 把 [recordings/](recordings) 里原有的 24 段录制送进检测器，打印每类动作识别到的事件数。录制由 `tools/h5_to_json.py` 从 Ring Studio 的 `.h5` 转换（需要 `h5py`）。新增的四个方向录制位于 `recordings/方向/`；每类只有一段，包含主动作和回程，且「上」原始文件标记为不完整、有 14 处时间不连续。它们没有逐次动作的时间标签，不能直接把所有波峰按文件名训练或计算准确率。

右手方向识别使用击拍前约 150 ms 的有符号陀螺仪特征，与当前佩戴者校准得到的模板比较；特征相近时拒绝判断。击拍后的 340 ms 内不重复触发；在 420 ms 内若下一次旋转方向与上次几乎相反，也会作为回程抑制，因此快速连续的相反方向击拍可能被漏掉。右手相邻时间戳间隔不超过 65 ms 时保留未完成峰值和历史；方向窗口最多允许一次超过 30 ms 的间隔，且须有至少 80 ms 的连续数据覆盖，不插造数据。更长间断会清除未完成峰值和方向历史，但保留击拍间隔与回程抑制状态；时钟倒退仍会重置校准。短间断跨过实际峰值时，峰值时间和方向仍可能不准确。设备轴向随佩戴方式改变，这不是通用方向模型。较慢的回程仍可能被识别成反方向，实际连续挥拍、换人及换佩戴方式后的准确率尚未验证，建议补采带逐次主动作和回程标注的数据并进行真机测试。

`npm test` 包含方向校准、断帧和方向不确定处理；四段新录制中选取的候选动作回放及每个方向一次移除约 50 ms 数据的模拟；戒指事件进入三拍、四拍关卡的方向与时间判定；以及延迟回填和桥接服务转发。候选动作不是独立人工标注的测试集，回放通过不代表真实使用准确率。


## 舞台与检查

舞台由 Three.js 实时绘制：夜场音乐厅，深色木地板、酒红帷幕、管风琴背景、青色灯带、指挥台和乐谱架。13 位坐姿乐手有面部、头发、礼服、手臂、椅子和乐器；声部启用后分别拉弓、弹键或呼吸。右手持棒，左手指人、抬掌、压掌。所有模型、木纹和谱页均由代码绘制，不使用游戏素材或背景画。

`npm test` 检查实际 Three.js 场景几何、13 位乐手的点击射线、右手上下左右平移、光圈、回放清理、三首关卡的谱面时间，以及每个右手音符都落在鼓点和钢琴和弦上。音符层（[src/lane.js](src/lane.js)）使用画布桩测试轨迹和左手记号，也需要在浏览器里目视检查；测试替换了 GPU 渲染器，不代替真实浏览器画面与音频检查。`npm run build` 生成生产版本。
